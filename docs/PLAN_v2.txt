**ARCHITECTURE DES DONNÉES**

🟩 Les Parquet constituent les sources de préparation des données.
🟩 Ils ne sont pas utilisés directement par le dashboard en production.
🟩 Les données nécessaires au dashboard sont transférées dans une base SQLite.
🟩 Une API dédiée permet au dashboard d'interroger cette base.
🟩 La table SQLite conserve les données FE complètes.
🟩 L'API ne charge jamais l'ensemble de la table en mémoire.
🟩 Les données de population sont échantillonnées au niveau des requêtes API.

**FLUX**

Parquet
↓
Préparation / transformation
↓
SQLite
↓
API données
↓
Dashboard Streamlit

**CONSÉQUENCE**

Les fichiers :

• `dashboard_clients.parquet`
• `feature_engineering.parquet`
• `global_feature_importance.parquet`

deviennent des fichiers intermédiaires de préparation, et non des dépendances de production du dashboard.

**PRINCIPE D'OPTIMISATION**

🟩 SQLite conserve la population complète.
🟩 Les requêtes client récupèrent uniquement le client demandé.
🟩 Les requêtes population récupèrent un échantillon limité.
🟩 Le dashboard ne charge jamais les 307511 lignes en mémoire.
